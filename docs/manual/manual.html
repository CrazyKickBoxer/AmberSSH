Chapter 1Introduction

AmberSSH is an SSH terminal for Windows 11. It speaks real SSH through libssh2, runs a real VT100/xterm-256color terminal over a genuine text-cell model, and then does something no other terminal does: it draws every glyph on screen as a small cloud of particles, simulated on the GPU, that assemble into letterforms, breathe, and scatter when the text changes.

The idea that makes this work is simple and worth stating up front: particles are presentation, never truth. Underneath the renderer there is an ordinary grid of characters with scrollback, an alternate screen, a cursor and attributes. Selection, copy, search, the command journal and every other feature operate on that grid. Whatever the particles are doing at the moment you drag across a line, what lands on the clipboard is exactly what the server sent.

Everything else in this manual — the fifteen interface skins, twenty-three arrival styles, the command journal, output folding, SFTP, workspaces — sits on top of that separation. Effects are subtle by default and every one of them can be turned off. The terminal has to stay readable; that is the whole point.

What you need

  • Windows 11, x64.
  • A GPU with DirectX 12. Integrated graphics are fine at the default particle density; the higher densities want a discrete card.
  • An SSH server to talk to. AmberSSH also opens serial lines, Telnet and Rlogin, and can play back terminal recordings with no server at all.

How this manual is organised

Chapters 2–4 get you connected and working. Chapters 5–12 cover the features that make AmberSSH more than a terminal. Chapter 13 is security, read it once. Chapters 14–16 are the visual system. The rest is reference.

Chapter 2Getting started

2.1 First run

AmberSSH is portable. Unzip it anywhere and run AmberSSH.exe. It keeps its own data under %LOCALAPPDATA%\AmberSSH (see Chapter 18) and writes nothing else to the machine.

The connection manager opens first: a category tree on the left, settings for the selected category on the right, and a Saved Sessions list with Load, Save and Delete. If you have used PuTTY the layout will be familiar on purpose.

2.2 Opening a session

  1. On the Session page enter a host name or IP address and a port (22 for SSH).
  2. Choose the connection type: SSH, Serial, Telnet or Rlogin.
  3. On Connection → Data enter the username, or leave it for the server to prompt.
  4. On SSH → Auth choose how to authenticate: password, a private key file (with its passphrase), keyboard-interactive, or an agent / Pageant.
  5. Press Open.

On first contact with a server AmberSSH shows the host, port, key algorithm and SHA-256 fingerprint and asks you to decide: accept once, accept and save, or cancel. The default is cancel. See Chapter 13 for what happens when a saved key later changes.

2.3 Saving a session

Fill in the settings, type a name in the Saved Sessions box and press Save. Every page's settings are stored with the profile. A saved session that remembers a password or passphrase stores the secret in the Windows Credential Manager, never in the profile file; the profile only records that a secret exists. Load restores a saved profile into the pages; Delete removes it along with its credentials.

2.4 Importing PuTTY and OpenSSH configurations

File → Import Profiles (also in the command palette) reads PuTTY's saved sessions from the registry and hosts from your OpenSSH config, and creates a profile for each one it does not already have. PuTTY .ppk private keys are not loaded — convert them to OpenSSH format first; the Auth page says so explicitly rather than failing later.

2.5 Private keys

Keys must be in OpenSSH format, of the types your libssh2 build supports (ed25519, ECDSA and RSA are the usual set). Choose the file on the Auth page with Browse…, and enter the passphrase there if the key has one. A passphrase you choose to remember goes to the Credential Manager like a password.

Windows Hello. File → Windows Hello for Stored Secrets puts a Hello prompt (face, fingerprint or PIN) in front of every use of a remembered password or passphrase. If verification fails the stored secret is simply not used and you are asked to type it.

Chapter 3The window

3.1 The title strip

AmberSSH draws its own title bar. From the left: the hamburger menu button (the application menu lives here — there is no conventional menu bar), the session tabs with an index tag and a close glyph each, the + button for a new session, and at the right the minimise, maximise and close buttons. On skins that number their tabs the tag is the tab's Ctrl+number shortcut.

Background tabs show a small activity spark while their session is producing output and burn red for a few seconds after an output trigger fires (Chapter 8). With Remote Vitals on (File menu), the strip shows the remote host's CPU, memory and network figures for the active session.

3.2 The status line and status bar

The status line is the transient message strip at the foot of the terminal — "Copied 412 characters", "Workspace saved", host-key results and so on. The status bar (View → Status Bar) is a thin permanent bar with clickable entries for the command journal, quake mode and the other overlays; every skin draws it in its own style.

F3 toggles the debug overlay: frame time, particle count, GPU timings and the renderer's state. F2 toggles VSync.

3.3 Sessions and tabs

ShortcutAction
Ctrl+Shift+TNew connection (opens the connection manager in a new tab)
Ctrl+Shift+WClose the tab — confirms first if the session is still connected
Ctrl+Shift+DDisconnect the session but keep the tab
Ctrl+Tab / Ctrl+Shift+TabNext / previous session

Each session runs on its own worker thread with its own grid and scrollback; a stalled session cannot block another. With Cube Session Switch on (Effects menu) switching tabs rotates the whole terminal like a Compiz desktop cube.

3.4 Split panes

Ctrl+Shift+E splits the active tab side by side, Ctrl+Shift+U top and bottom; Close Split keeps the focused pane. Click a pane or press Ctrl+Shift+arrows to move focus. Broadcast Input to Both Panes (File menu) types what you type into both — useful for the same command on two hosts.

3.5 Quake mode

File → Quake Mode registers Ctrl+` as a system-wide hotkey. Pressing it drops the terminal down from the top of the screen and pressing it again slides it away, from any application. If another program already owns Ctrl+` the status line tells you and quake mode stays off.

3.6 Full screen and the screensaver

F11 or Alt+Enter toggles full screen. Effects → Screensaver lets the particle field drift free after 1, 5 or 15 minutes of no input; any key or mouse movement brings the text back.

Chapter 4Working in the terminal

4.1 Selection and the clipboard

Drag with the left button to select. Releasing the button copies the selection automatically and the status line reports how many characters went to the clipboard. A click without a drag clears the selection. Right-click pastes. Ctrl+Shift+C and Ctrl+Shift+V (or Shift+Insert) do the same from the keyboard.

Local shortcuts deliberately use Ctrl+Shift so they can never collide with terminal control codes: Ctrl+C interrupts the remote process, Ctrl+Shift+C copies. Plain Ctrl combinations are sent to the shell.

Selected text switches from the amber ramp to the drifting Miami Sunset gradient (Effects → Miami Sunset Selection). The Selection page of the connection manager can make rectangular selection the default and set what the middle and right buttons do.

4.2 The paste guard

View → Confirm Multi-line Paste asks before sending any paste that contains a line break, showing what is about to be typed. A newline in a paste executes whatever precedes it; the guard exists so a copied paragraph cannot run as a series of commands by accident. Bracketed-paste mode is honoured when the remote application enables it.

4.3 Scrollback and search

The mouse wheel scrolls; Shift+PgUp / Shift+PgDn move a page at a time. Typing returns the view to the live bottom. The Terminal page sets the number of scrollback lines.

Ctrl+Shift+F opens Search Scrollback. Type a term and press Enter to find the nearest match above; Ctrl+G repeats the search and wraps when it reaches the top. Matches are highlighted in the live text.

4.4 Links and file paths

Ctrl+click a URL to open it in your browser. Ctrl+click a file path in the output and AmberSSH opens the SFTP browser at that file's directory with the file selected — the fastest way from "there's the file" to "here it is on my machine". If nothing usable is under the pointer the status line says so.

4.5 Font size and typing

Ctrl+Plus / Ctrl+Minus or Ctrl+wheel change the terminal font size. Keyboard input goes through the Windows layout engine, so dead keys and non-US layouts produce the right characters. Alt+drag pushes the particles around with the pointer force field without touching the text (Effects → Pointer Force).

4.6 The time dial

Hold Alt and scroll the wheel to turn the time dial: it slows every animation down (to 0.05×) or speeds it up (to 4×) without changing anything about the text. The status line shows the current factor. Motion → Reset Time Dial (or the palette) puts it back to 1×.

Chapter 5Shell integration

Several features need to know where one command ends and the next begins. AmberSSH reads the standard OSC 133 prompt marks that modern shells can emit — the same ones VS Code, WezTerm and iTerm2 use — plus OSC 7 for the current directory. Once your shell sends them you get:

  • Command jumping — Ctrl+Up / Ctrl+Down move the view to the previous / next command prompt in the scrollback.
  • Output folding — Ctrl+Shift+O collapses the output of the command at the cursor to a single summary line and expands it again. View → Fold All Output / Expand All Output do the whole scrollback. Folded lines are skipped by selection and search consistently: what you see is what you copy.
  • Exit-code flashes — a command that fails flashes its prompt line briefly in the danger colour.
  • Spotlight the running command (Effects) — while a command runs, everything except its output dims a little.
  • Taskbar progress — a long-running command shows progress on the taskbar button, and the button turns red on a non-zero exit while the window is in the background.
  • The command journal (Chapter 6).

5.1 Enabling the marks

For bash, add to ~/.bashrc:

__amber_prompt() { printf '\e]133;A\a'; }
__amber_precmd() { printf '\e]133;D;%s\a' "$?"; }
PROMPT_COMMAND='__amber_precmd; __amber_prompt'
PS0='\e]133;C\a'
PS1="${PS1}"'\[\e]133;B\a\]'
PROMPT_COMMAND="$PROMPT_COMMAND; printf '\\e]7;file://%s%s\\a' \"$HOSTNAME\" \"$PWD\""

For zsh, add to ~/.zshrc:

precmd()  { printf '\e]133;D;%s\a' "$?"; printf '\e]133;A\a'; printf '\e]7;file://%s%s\a' "$HOST" "$PWD"; }
preexec() { printf '\e]133;C\a'; }
PS1="${PS1}%{$(printf '\e]133;B\a')%}"

A marks the start of a prompt, B the start of input, C the start of a command's output and D its end with the exit code. Fish emits these out of the box.

Nothing in this chapter is required. Without the marks the terminal works exactly as before; the features above simply have nothing to attach to.

Chapter 6The command journal

The journal is a record of every command you have run in AmberSSH, on every host, with its working directory, exit code and how long it took. It is captured from the shell-integration marks (Chapter 5), so it needs them, and it is stored locally in journal.jsonl. Nothing is ever sent anywhere.

File → Record Commands to Journal turns capture on and off. Clear Command Journal… forgets everything after a confirmation.

6.1 The overlay

Ctrl+Shift+J opens the journal as an overlay on the terminal. Start typing to filter — the search matches the command, the host and the directory. Each entry shows when it ran, on which host and where, its exit code (failed commands are marked) and its duration.

Chapter 7The command palette

Ctrl+Shift+P opens a fuzzy-matching list of every action in the application. Type a few letters of what you want — "fold", "sftp", "theme bra" — and press Enter. ↑ ↓ move, Esc closes.

The palette contains, among others: New Connection, Close Tab, Disconnect, Split Vertical / Horizontal, Close Split, Toggle Fullscreen, SFTP Panel, Import Profiles, Search Scrollback, Log Session to File, Customize Theme, Diagnostic Screen, Font Size Larger / Smaller, every Theme:, every Font:, Reduced Motion, Reset Time Dial, About, Command Journal (open / record / clear), Density: Auto, both colour palettes, both render modes, Previous / Next Command Mark, Paste, Fold / Fold All / Expand All, every saved Snippet:, Edit Snippets, Edit Output Triggers, Play Recording, Port Forwarding / Jump Host, and Next / Previous Session.

Snippets (Chapter 8) appear here as Snippet: name, which is the intended way to run them.

Chapter 8Snippets and output triggers

8.1 Snippets

File → Edit Snippets… opens snippets.txt in your editor. One snippet per line:

# AmberSSH snippets — one per line:   name = command
# {host} {user} {port} expand from the active session; any other {name}
# prompts for a value. A literal \n sends Enter. Run them from the
# command palette (Ctrl+Shift+P, type the name).
tail-syslog = sudo tail -f /var/log/syslog\n
disk = df -h {mount}\n
whoami-here = echo {user}@{host}:{port}\n

{host}, {user} and {port} are filled in from the active session. Any other {name} prompts you for a value when the snippet runs. A literal \n sends Enter, so a snippet without one is typed but not executed. Run a snippet from the command palette by typing its name.

8.2 Output triggers

File → Edit Output Triggers… opens triggers.txt, one regular expression per line (ECMAScript syntax, case-insensitive):

# AmberSSH output triggers — one regular expression per line
# (ECMAScript syntax, case-insensitive). When a line of output matches:
# the status line shows it, the visual bell rings, and a Windows
# notification appears if the window is in the background.
build (succeeded|failed)
^error:
segmentation fault

When a line of output matches, the status line shows the line, the visual bell fires (the shockwave, if it is on), the tab's activity spark burns red for a few seconds, and a Windows notification appears if the window is in the background. Triggers are a way to walk away from a long build.

Chapter 9The SFTP browser

Ctrl+Shift+B (or File → SFTP Browser) opens a two-pane file browser over the active session's connection: your machine on the left, the remote host on the right, and a transfer queue beneath. It needs a connected SSH session. The browser has its own tabs (Ctrl+T new, Ctrl+W close) so several hosts can be open at once.

Chapter 10Workspaces

A workspace is a named set of sessions you open together. Open the sessions you want, then File → Workspaces → Save Workspace… and give it a name. Later, choosing the workspace from the same menu (or from the command palette) opens every session in it, each in its own tab.

  • A workspace stores saved profiles, so every session in it must be a saved session first — the status line says so if one is not.
  • Split panes are reopened as separate tabs.
  • Workspaces live in workspaces.jsonl; the menu offers Delete for each.

The application also remembers the last set of open sessions and offers to reopen them; workspaces are for sets you return to deliberately — "the three build boxes", "prod and its bastion".

Chapter 11Logging and recording

11.1 Session logs

Ctrl+Shift+L starts and stops logging the session's output to a text file. The Logging page of the connection manager sets it up per profile: what to log (all session output, or nothing), the file name with date and host tokens (Y M D date, T time, H host, P port), whether to append to an existing file or overwrite it, and whether to flush frequently. When a profile has logging configured it starts as soon as the session opens; Ctrl+Shift+L still toggles it.

The log is the terminal stream, so passwords typed at a prompt that does not echo are not in it — but anything the server prints is. Treat logs as sensitive.

11.2 Recording and playback

File → Record Session (asciinema)… writes an .cast file — the asciinema v2 format, so it plays in any asciinema player and on asciinema.org. File → Play Recording… plays a .cast file in a local tab with no server involved: the recording is fed through the same terminal and the same particles as a live session, with every effect and skin applied. AmberSSH also starts in playback mode from the command line: AmberSSH.exe --play recording.cast.

Chapter 12Port forwarding and jump hosts

File → Port Forwarding / Jump Host… edits the forwards for the active session; the SSH → Tunnels page stores them with a profile. One forward per line, in OpenSSH's notation:

L8080:localhost:80        # local 8080 → port 80 on the remote host
L5432:db.internal:5432    # local 5432 → a host only the server can reach
R9000:localhost:3000      # remote 9000 → port 3000 on this machine
D1080                     # SOCKS proxy on local 1080

The SSH page's Jump host (user@host[:port]) connects through a bastion first and opens the real session over it. Don't start a shell or command at all turns a profile into a pure tunnel: the session connects, opens its forwards, and shows no prompt.

Chapter 13Security

13.1 Credentials

Passwords and key passphrases are never written to disk by AmberSSH. A secret you choose to remember goes to the Windows Credential Manager under AmberSSH/{profile-uuid}/password or …/key-passphrase; profiles.json records only a boolean saying one exists, and a unit test asserts the file contains no secret fields. A secret you do not remember lives only in a zeroed-on-destruction buffer for the life of the connection. Deleting a profile erases its credentials. Windows Hello for Stored Secrets (File menu) adds a Hello check before any stored secret is used.

What this does not do: lock pages. A secret must exist in memory to be handed to libssh2, and the operating system may page that memory.

13.2 Host keys

The server's host key is checked after every handshake. On first contact you see the host, port, algorithm and SHA-256 fingerprint and must choose: accept once, accept and save, or cancel (the default). Saved keys are kept in known_hosts under the profile's logical host name (SSH → Host keys).

A changed key is treated as a serious failure. AmberSSH never continues silently: it shows the expected and received fingerprints, explains that this is either a rebuilt server or an interception attempt, and requires a separate, explicit action to replace the stored key.

13.3 The terminal as untrusted input

Everything a remote host sends is treated as hostile data. The parser bounds its parameter arrays and clamps values, caps OSC payloads at 4 KB (a 200 KB title attempt is a regression test), recovers from malformed sequences without corrupting state, decodes UTF-8 defensively, and no escape sequence can run an operating-system command. The paste guard (Chapter 4) protects the other direction.

13.4 What is and is not there

  • No telemetry, no log upload, no automatic host-key acceptance.
  • The logger never receives secret material.
  • Encryption preferences (ciphers, key exchange, host-key algorithms) are configurable on the SSH page; blank means the built-in modern defaults.
  • .ppk keys are not read; convert them.

Chapter 14The look: appearance, themes and interface skins

Three independent choices decide how AmberSSH looks. Appearance is the ground the terminal is drawn on. The theme is the colour ramp the particles glow in. The interface skin is what everything around the terminal — title strip, menus, dialogs, SFTP browser — is made of. Any combination works.

14.1 Appearance (View menu)

ModeWhat it is
DarkBlack glass. The default; the particles glow additively on it.
Light (paper)A light ground with dark ink; the glow becomes a soft halo.
PaperwhiteWarm e-ink: the whole image is composited to greyscale on paper.
Pixel ArtThe PICO-8 sixteen-colour palette, pixelated in the composite.

Alongside these: Text Shadow (Off / Soft / Medium / Strong) drops a shadow under the crisp core, and Text Sharpness chooses Soft (the glow over the letter), Crisp (the letter over the glow) or Razor (the letter drawn after bloom, for maximum legibility).

14.2 Themes (View menu)

A theme is a five-stop colour ramp from dim to hot. Amber Nixie · Emerald CRT · Ice Cathode · Violet Haze · Blood Cell · Paper White · Brass Gaslight — and Custom, edited in Customize Theme… with three colour pickers. The Colours page can also set an ANSI palette per profile: Amber Miami maps the sixteen colours onto the theme, Classic xterm keeps them.

Per-host rules. A theme can follow the host: rules of the form pattern=themeId, comma-separated, with * wildcards (*.prod.*=4,bastion=2). First match wins. The same mechanism exists for motion styles.

Night Shift (Effects) warms the whole image: Off, After dark (by the clock), or Always warm.

14.3 Text

Font chooses the terminal face: JetBrains Mono, Cascadia Mono, Consolas, Courier New, Lucida Console, Cascadia Code, Fira Code, Hack, Source Code Pro, IBM Plex Mono, Iosevka, Space Mono, Ubuntu Mono, or a custom family. Open-source faces that are not installed are downloaded the first time you pick them and kept in the fonts folder. Font Style chooses Modern (the crisp core), Dot Matrix 8-pin or Dot Matrix 12-pin — the particles quantise to a printer pin grid. Render chooses Particle + Crisp Core (the default) or Particles Only. Syntax Tint colours recognisable output — paths, numbers, errors — by kind.

15.2 Departure styles

Fade, Ash (particles lift and grey), Smoke (they curl upward), Sand (they pour down), Shatter (they fly apart). A departing particle is taken off its spring, so the two axes never fight.

15.3 Reduced motion

Motion → Reduced Motion replaces every depth effect, flash and rotation with a short Direct morph. It is the accessibility setting and it overrides every style.

Chapter 20Terminal compatibility

AmberSSH announces TERM=xterm-256color by default; the Terminal page can send screen-256color or xterm-direct instead.

Supported

  • Control characters BEL, BS, HT, LF, VT, FF, CR; UTF-8 including sequences split across reads.
  • ESC 7 / 8 save and restore cursor, D index, M reverse index, E next line, c reset, ( 0 and ( B charset selection.
  • CSI cursor movement (CUU/CUD/CUF/CUB, CNL/CPL, CHA, VPA, CUP/HVP), ED and EL, ICH, DCH, ECH, IL, DL, SU, SD, DECSTBM, SCP/RCP, DSR, DA, DECSCUSR, SGR, DEC private modes.
  • SGR reset, bold, dim, italic, underline, blink, reverse, hidden, strikeout, sixteen colours, 256-colour and truecolour.
  • DEC modes ?1 application cursor keys, ?7 autowrap, ?25 cursor visibility, ?1049 / ?47 alternate screen, ?2004 bracketed paste, ?1000–?1003 mouse tracking.
  • OSC 0 and 2 (window title), 7 (working directory), 52 (clipboard), 133 (prompt marks). Unknown OSCs are consumed and ignored.

Partial or not supported

  • Mouse tracking modes are accepted; pointer events are forwarded to applications that ask for them.
  • OSC 8 hyperlinks are consumed; Ctrl+click works on the visible URL text.
  • No Sixel or ReGIS graphics, no double-width / double-height lines, no rectangular-area operations.

Every supported item has unit coverage; the parser is written against hostile input (Chapter 13).

Chapter 21Building from source

Windows 11 x64, Visual Studio 2022 or the Build Tools with the Desktop C++ workload and the Windows 11 SDK, CMake 3.24+, and vcpkg with VCPKG_ROOT set.

.\build.ps1                       # Release
.\build.ps1 -Config Debug -Test   # Debug, then the unit tests
.\build.ps1 -Clean                # wipe build\ first
.\package.ps1                     # portable ZIP + SHA-256 in dist\

Or by hand:

cmake -S . -B build -G "Visual Studio 17 2022" -A x64 `
  "-DCMAKE_TOOLCHAIN_FILE=$env:VCPKG_ROOT\scripts\buildsystems\vcpkg.cmake"
cmake --build build --config Release
.\build\tests\Release\AmberTests.exe

HLSL is compiled to DXIL by DXC as a build step; a shader error fails the build, and a contract test parses the HLSL to make sure the constant buffers still match the C++ side. Dependencies come from the vcpkg manifest: libssh2, OpenSSL, nlohmann-json, Catch2, directx-dxc.

Chapter 22Troubleshooting

SymptomWhat to do
"Could not register Ctrl+`"Another application owns the hotkey. Quake mode stays off until it is free.
The window opens but the terminal is blank or slowThe GPU or driver may not support DirectX 12 well. Set Density to Performance, turn Bloom to Low, and check F3 for frame times.
A skin's typeface looks wrong the first timeIts font is being fetched; the installed fallback is used until it arrives, and the status line says when it has.
"Windows Hello verification failed — stored secrets not used"The Hello prompt was cancelled or failed. Type the secret, or turn the gate off in the File menu.
Host key changedDo not accept it casually. Confirm with the server's administrator that the key was regenerated before replacing the stored one.
Command jumping, folding or the journal do nothingThe shell is not emitting OSC 133 marks. See Chapter 5.
A pasted paragraph asked for confirmationThat is the paste guard. Confirm it, or turn it off in View → Confirm Multi-line Paste.
The SFTP browser will not openIt needs a connected SSH session in the active tab; serial, Telnet and playback tabs have no file channel.
Too much movementMotion → Reduced Motion, or turn the time dial down with Alt+wheel.
